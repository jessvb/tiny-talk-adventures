WHAT IF?

Built for one family. What would it take to reach every child?

Tiny Talk was built for one household with a Mac at home. Here are four constraints I haven't built for yet, what each one would change in the architecture, and what I'm still unsure about. Toggle each diagram between today and the what-if.

IN EVERY SCENARIO

The architecture changes. These principles don't.

The child can always interrupt

Stopping Elsie is decided on the device, never across a network. Every design keeps that path local.

A child's voice travels as little as possible

Audio and photos stay on the closest hardware that can handle them. When they have to leave, they're processed and not stored.

Grown-ups can see where Elsie's brain is

Whichever path is active, settings name it in plain words, like the away-mode warning does today.

One safety gate, on every path

Swapping a model never means swapping the rules. Every route passes through the same check before anything reaches the child.

Facts come from sources

Whether fetched live or bundled for offline use, facts come from a reference, not the model's memory.

Measure on the real hardware first

Each scenario starts the same way the Mac version did: probe the target device, then choose the models.
